# IronCord v2 Security Guide

This document outlines security requirements, best practices, and deployment guidelines for IronCord v2.

---

## Production Deployment Checklist

Before deploying to production, ensure all items are completed:

### 🔐 Secrets Management

- [ ] **Create `.env` file** from `.env.example` template
- [ ] **Generate secure JWT_SECRET** (min 32 characters)
  ```bash
  # Linux/Mac:
  openssl rand -base64 32
  
  # Windows PowerShell:
  [Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }))
  ```
- [ ] **Set strong database password** (min 16 characters, mix of letters/numbers/symbols)
- [ ] **Verify `.env` is gitignored** (should already be in `.gitignore`)
- [ ] **Never commit `.env` to version control**

### 🌐 CORS Configuration

- [ ] **Set `CLIENT_ORIGIN`** to your frontend domain (e.g., `https://ironcord.example.com`)
- [ ] **Never use wildcard (`*`) in production**

### 🔒 HTTPS/TLS

- [ ] **Use reverse proxy** (nginx, Caddy, Traefik) with valid TLS certificates
- [ ] **Redirect HTTP → HTTPS**
- [ ] **Enable HSTS header** (`Strict-Transport-Security`)
- [ ] **Use strong cipher suites** (TLS 1.2+)

### 🛡️ Container Security

- [ ] **Run Podman/Docker in rootless mode** (if supported by your environment)
- [ ] **Do not use `--privileged` flag**
- [ ] **Limit container resources** (CPU, memory)
- [ ] **Use container registry scanning** (e.g., Trivy, Clair)
- [ ] **Keep base images updated** (`node:20-alpine`, `postgres:15-alpine`)

### 📊 Monitoring & Logging

- [ ] **Enable application logging** (already configured via `@ironcord/shared` logger)
- [ ] **Setup log aggregation** (e.g., ELK stack, Loki)
- [ ] **Monitor for failed login attempts**
- [ ] **Setup alerting for security events**

### 🔄 Dependency Security

- [ ] **Run `npm audit`** and fix critical/high vulnerabilities
  ```bash
  npm audit
  npm audit fix
  ```
- [ ] **Setup automated dependency scanning** (Snyk, Dependabot, Renovate)
- [ ] **Keep dependencies updated** regularly

### 🔐 Database Security

- [ ] **Use strong PostgreSQL password** (generated by secure random method)
- [ ] **Limit database network exposure** (use internal Docker network only)
- [ ] **Enable PostgreSQL SSL/TLS** for connections
- [ ] **Regular database backups** with encryption
- [ ] **Principle of least privilege** for database user

## Security Features

### ✅ Implemented Security Controls

#### Authentication & Authorization
- **bcrypt password hashing** with 10 rounds (OWASP compliant)
- **JWT tokens** with 24-hour expiration
- **Token verification** on all protected endpoints
- **WebSocket authentication** via JWT in handshake
- **Generic error messages** to prevent user enumeration

#### Input Validation
- **Email format validation** (regex pattern)
- **Password minimum length** (8 characters)
- **Type checking** on all inputs
- **Request validation middleware**

#### SQL Injection Prevention
- **Parameterized queries** exclusively (no string concatenation)
- **PostgreSQL prepared statements** via `pg` library
- **Type-safe database repositories**

#### XSS Prevention
- **React JSX escaping** by default
- **No `dangerouslySetInnerHTML`** in codebase
- **Content-Type headers** properly set
- **Sanitized error responses**

#### CORS Protection
- **Environment-based CORS** (restrictive in production)
- **Credentials support** with `credentials: true`
- **Origin validation**

#### Information Disclosure Prevention
- **Stack traces** only in development mode
- **Sensitive data excluded** from logs (passwords, tokens)
- **Generic 500 errors** in production

#### Dependency Security
- **Strict TypeScript** compilation (no `any` types in production code)
- **Minimal dependencies** (small attack surface)
- **Pinned versions** for critical dependencies

## Known Security Considerations

### Container Root User

**Status**: ⚠️ **Accepted Risk**  
**Reason**: Supervisor process manager requires root to manage multiple processes (Gateway + IRC)

**Mitigations**:
1. Container isolation via Podman/Docker namespaces
2. No privileged mode required
3. Alpine Linux minimal attack surface
4. Read-only filesystem where possible
5. Network isolation via Docker bridge network

**Future Improvement**: Migrate to separate containers for Gateway and IRC server

### Development Fallback Credentials

**Status**: ✅ **Mitigated**  
**Reason**: Development mode allows fallback secrets for ease of local development

**Mitigations**:
1. Runtime check prevents production deployment with defaults (see `apps/gateway/src/config/env.ts:31-53`)
2. Application throws error on startup if insecure secrets detected in production
3. Required environment variables enforced via podman-compose.yml (`:?` syntax)

## Incident Response

### In Case of Security Breach

1. **Immediate Actions**:
   - Stop affected containers: `podman compose down`
   - Rotate JWT_SECRET immediately
   - Invalidate all existing sessions
   - Reset all user passwords (force password reset)

2. **Investigation**:
   - Review application logs
   - Check database audit logs
   - Analyze network traffic
   - Identify breach vector

3. **Remediation**:
   - Patch vulnerability
   - Update dependencies
   - Rebuild and redeploy containers
   - Notify affected users (if applicable)

4. **Post-Incident**:
   - Document incident and response
   - Update security controls
   - Review and improve monitoring

## Security Testing

### Manual Testing Checklist

- [ ] **SQL Injection**: Try `' OR '1'='1` in login form
- [ ] **XSS**: Try `<script>alert('XSS')</script>` in text inputs
- [ ] **Authentication Bypass**: Try accessing `/guilds/mine` without JWT
- [ ] **CSRF**: Verify CORS blocks unauthorized origins
- [ ] **Brute Force**: Test rate limiting (if implemented)
- [ ] **Session Expiry**: Verify JWT expires after 24h

### Automated Security Scanning

```bash
# Dependency vulnerabilities
npm audit

# SAST (Static Application Security Testing)
# Example with Snyk:
npx snyk test

# Container scanning
# Example with Trivy:
trivy image ironcord-unified:latest

# OWASP ZAP
# Run against running instance (manual setup required)
```
